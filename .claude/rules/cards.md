# Karpathy Wiki 约定

## 文件夹结构

- index.md — 全局内容入口，Query 时先读
- overview.md — 当前综合认知与主要未知项
- log.md — Ingest / Query / Lint 的时间记录
- 21-IndexCard-索引卡/ — LLM 维护的主题与人物导航
- 22-BibCard-阅读卡/ — LLM 维护的来源摘要与事实页
- 23-MainCard-核心卡/ — LLM 维护的概念、比较与综合页

## 命名规范

- 索引卡：`K编号-关键词.md`（如 K101-个人生产力.md）
- 编号由用户手动指定，**一旦分配不再改变**

## Wiki 编译流转

Raw Source → Ingest → 来源摘要 → 更新既有概念页/索引 → Overview → Log

用户复述或实践先保存在 Daily 或 `x/`，再作为新的 Raw Source 被 Ingest；不能由 AI 直接编造成“用户观点”。

## 操作规则

- 创建核心卡：Frontmatter 必须写 `创建日期` + `AI 备注`；可选填 `index`，不添加其他属性
- 核心卡 `index` 只作可选导航提示；操作时只用 21-IndexCard-索引卡/ 中已有索引卡，不新建
- LLM 可以直接维护来源摘要、概念页、交叉引用、既有索引、Overview 和 Log
- 新建主题编号仍由用户确认；既有主题下的双链维护不需要逐次确认
- 涉及使用者的身份、观点、目标和决定时，必须引用用户原始来源与时间；不允许从 AI 草稿反推用户事实
- 删除、覆盖有意义内容或解决真实语义矛盾前，必须让用户确认

## 可检索提示词卡

- 经使用者原样说“收下这个提示词”，或紧接可验证的提示词快捷菜单回复单个数字“1”的公开来源，可以在保留 `x/` Raw 后编译为 `23-MainCard-核心卡/提示词-<用途>.md`，并同时接入已经存在的内容创作索引与全局 `index.md`
- 数字 `1` 不是全局确认词；只有同一私聊的最近用户原话、前一轮完整 1/2/3 菜单、180 秒时效和一次性消费同时通过工具校验时才能暂存
- 一条可独立调用的 Prompt 对应一张卡；文件名按用途命名，不照抄来源营销标题
- 卡片顶部只保留召回所需的触发需求、适合素材、目标效果和不适合场景；完整 Prompt 在正文代码块中原样保存，不优化、不删减；页面标题中的短截断块不能替代正文中明显更长的完整块
- 调用信息是 LLM 结构化元数据，来源展示不等于使用者已测试或认可；卡片必须链接原始 Raw 与公开 URL
- 同一准确 Prompt 的重复来源不得无声覆盖既有卡；无法确定是否相同时保留独立记录，之后再由 Ingest/Lint 合并判断
